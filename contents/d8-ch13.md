## Section 8: Writing More Pythonic Code

By now, you’ve learned a wide range of Python features — comprehensions, lambda functions, built-ins, generators, and more. The next step is learning how to use them **well**.

Writing **Pythonic code** means writing code that is:

* Clear
* Concise
* Readable
* Idiomatic (aligned with how Python is meant to be used)

This section focuses on patterns and habits that will improve your code quality.

---

### Prefer Readability Over Cleverness

Python values clarity above all else.

Bad (too clever):

```python
result = [x*x for x in data if x%2==0 and x>10 and x<100]
```

Better:

```python
result = [x * x for x in data if 10 < x < 100 and x % 2 == 0]
```

Even better (if logic grows):

```python
result = []
for x in data:
    if 10 < x < 100 and x % 2 == 0:
        result.append(x * x)
```

> **Helpful Hint:**
> If you have to stop and mentally decode your own code, it’s probably not Pythonic.

---

### Replace Loops with Simpler Constructs

Instead of:

```python
names = []
for plane in planes:
    names.append(plane["name"])
```

Use:

```python
names = [plane["name"] for plane in planes]
```

---

### Avoid Unnecessary Variables

Instead of:

```python
value = get_range(plane)
return value
```

Use:

```python
return get_range(plane)
```

---

### Use Built-ins Instead of Manual Logic

Instead of:

```python
found = False
for r in ranges:
    if r > 5000:
        found = True
        break
```

Use:

```python
found = any(r > 5000 for r in ranges)
```

---

### Write Clear Conditional Logic

Instead of:

```python
if is_ready == True:
```

Use:

```python
if is_ready:
```

Instead of:

```python
if is_ready == False:
```

Use:

```python
if not is_ready:
```

---

### Use Meaningful Names

Bad:

```python
x = [p["name"] for p in planes]
```

Better:

```python
plane_names = [plane["name"] for plane in planes]
```

Clear naming reduces the need for comments.

---

### Keep Functions Focused

A good function should:

* Do one thing
* Be easy to test
* Be easy to understand

Bad:

```python
def process_planes(data):
    # loads data
    # filters
    # sorts
    # prints
```

Better:

```python
def filter_planes(data):
    ...

def sort_planes(data):
    ...
```

---

### Refactoring Example

Before:

```python
result = []
for plane in planes:
    if plane["range"] > 5000:
        result.append(plane["name"])
```

After:

```python
result = [plane["name"] for plane in planes if plane["range"] > 5000]
```

Cleaner, shorter, and easier to read.

---

### Consistency Matters

Stick to consistent patterns:

* Naming style (snake_case)
* Indentation and spacing
* Structure of functions and files

Consistency makes your code easier to maintain and collaborate on.

---

> **Helpful Hint:**
> Python has an official style guide called **PEP 8**. You don’t need to memorize it, but following its general ideas will make your code more professional.

---

### Summary

Writing Pythonic code means:

* Choosing clarity over cleverness
* Using the right tools (comprehensions, built-ins, etc.)
* Writing code that others can quickly understand
* Keeping functions simple and focused
