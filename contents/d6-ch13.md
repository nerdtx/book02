
## Section 6: Error Handling Best Practices

No program is perfect. Users enter unexpected input, files go missing, and network calls fail. Good software doesn’t just work when everything goes right — it handles things gracefully when something goes wrong.

In this section, you’ll learn how to properly use Python’s error handling tools and write more robust, reliable code.

---

### What Is an Exception?

An **exception** is an error that occurs while a program is running. When an exception happens, Python stops normal execution and raises an error.

Example:

```python
num = int("abc")  # ValueError
```

This crashes the program unless you handle it.

---

### Using `try` and `except`

You can catch exceptions using a `try`/`except` block:

```python
try:
    num = int("abc")
except ValueError:
    print("Invalid number!")
```

Now the program continues instead of crashing.

---

### Catching Specific Exceptions

It’s important to catch **specific exceptions**, not everything:

```python
try:
    result = 10 / 0
except ZeroDivisionError:
    print("You can't divide by zero!")
```

Avoid this pattern:

```python
except:
    print("Something went wrong")  # Too vague
```

This can hide real bugs and make debugging difficult.

---

### Using `else` and `finally`

You can extend error handling with `else` and `finally`:

```python
try:
    num = int("42")
except ValueError:
    print("Invalid input")
else:
    print("Success:", num)
finally:
    print("This always runs")
```

* `else` runs only if no exception occurred
* `finally` always runs (useful for cleanup)

---

### Raising Your Own Exceptions

You can raise exceptions intentionally using `raise`:

```python
def set_altitude(altitude):
    if altitude < 0:
        raise ValueError("Altitude cannot be negative")
    print("Altitude set to", altitude)
```

This is useful for enforcing rules in your code.

---

### Writing Defensive Code

Instead of waiting for errors, you can prevent them:

```python
user_input = input("Enter a number: ")

if user_input.isdigit():
    num = int(user_input)
else:
    print("Please enter a valid number")
```

This avoids raising an exception in the first place.

---

### Logging and Debugging

In larger applications (like your Bottle or Peewee apps), you may want to log errors instead of just printing them:

```python
try:
    # some operation
    pass
except Exception as e:
    print("Error occurred:", e)
```

Later, you might replace this with structured logging.

---

> **Helpful Hint:**
> Don’t use exceptions to control normal program flow. Use them for truly exceptional situations, not everyday logic.

---

### Summary

Good error handling helps you:

* Prevent crashes
* Provide helpful feedback to users
* Debug issues more easily
* Build more reliable applications
